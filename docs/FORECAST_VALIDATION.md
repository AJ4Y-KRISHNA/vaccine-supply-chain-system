# Reproducible advisory forecasting

The default HTTP forecast now compares three deterministic baselines: last observation, trailing-three mean and historical drift. It selects by expanding-window MAE on a chronological prefix, then reports MAE, RMSE and WAPE for every baseline on the same untouched later suffix. WAPE is null for an all-zero denominator. The forecast is one supplied period ahead using the latest observations; units and a SHA-256 of the input series accompany the result. No per-request model fitting or random seed is involved.

Inputs must contain 6–240 finite nonnegative equally spaced observations for one product/region. Caller-provided arrays remain unverified: the API cannot establish their provenance or time spacing. Operator-configured CSV files must have contiguous unique chronological `month` (YYYY-MM) and `doses` columns. Only configured WHO_MI4A_CSV/UNICEF_SHIPMENTS_CSV paths may be read; filenames do not confer authoritative status. A configured missing/invalid file raises an error rather than silently substituting demo data. With no configured data, the existing fixed demo series is explicitly returned as synthetic, not observed demand.

The original CNN-LSTM remains an **experimental, unused-by-default** module. Its prediction now uses the latest three observations with the existing training scaler; deterministic seed 42 and non-shuffled training replace uncontrolled training. No claim is made that it outperforms baselines or has been prospectively validated. Obtaining representative, licensed product/region demand history and running independently held-out experiments remains a research prerequisite.

The decision API is advisory and no longer invokes the Python blockchain oracle. Integer replenishment suggestions and sentiment-based risk are not a constrained allocation. Only the authenticated backend can sign local transactions. BERT initialization/download is opt-in (`ENABLE_EXPERIMENTAL_BERT=true`); default sentiment uses the existing explicitly labeled heuristic fallback, not a trained-model claim.

Run `python -m unittest discover -s tests -v` from `ai-services`. Five tests cover reproducibility, latest-window behavior, no future-data leakage in selection, baseline comparison, invalid/all-zero data, explicit synthetic provenance and dataset path restrictions. A FastAPI decision-route smoke check passed. Metrics on these fixtures demonstrate software behavior only—not real vaccine demand accuracy. Existing historical forecast/certificate fields are not promoted to validated predictions.
